# 企业 PKI 业务配置与使用

状态：当前指南；核对日期：2026-11-15。先完成 [部署](production-deployment.md)。
当前不承诺支持 CFSSL 全部 CLI 能力，接口清单以 [OpenAPI](openapi.yaml)为准。

## 建立 CA 层级

超级管理员创建根 CA，再选择根创建中间 CA。常见配置是根 `path_length=1`、中间
`path_length=0`，由中间签发叶证书。叶证书不计入 CA 深度，根设为 0 后不能签发中间。
背景见 [RFC 5280](https://www.rfc-editor.org/rfc/rfc5280.html#section-4.2.1.9)。

创建生成 RSA-4096 根（名义有效期 10×365 天）和 RSA-3072 中间 CA（3×365 天），
子证书有效期受整条上级链限制。新建深度允许 0–5；创建接口的中间 CA 上级必须为根。
已有根和多级中间可按从上到下顺序 [导入](ca-import.md)，支持中间作为上级，
保留原证书约束，`path_length=-1` 表示原证书不限深度；不导入历史叶证书和吊销记录。

CA 私钥加密存库，运行时解密用于签名。这是在线软件 CA，当前没有离线根签署、
仅证书托管或 HSM/PKCS#11 接口。新建/导入保存默认模板和委托 OCSP 响应者。
初始 CRL 在 CA 保存后生成；失败会记录日志，CA 仍可能创建成功，需单独检查 CRL 地址。

## 用户和授权

| 角色 | 当前主要能力 |
| --- | --- |
| 超级管理员 | 用户、CA、密钥导出、模板、授权、TSA、审计；处理他人申请 |
| 运维人员 | 在授权中间 CA 上查看、审批、吊销；管理自身申请和证书 |
| 普通用户 | 提交申请、查看自身申请和证书、下载允许领取的材料 |

普通/运维账户用户名 3–128 字节、密码 15–128 字节；邮箱可选，填写时须通过接口校验。
建议随机 ASCII 密码，避免把字节限制当 Unicode 字符数。

给运维人员同时授予中间 CA 的 `view_requests` 和 `approve`，需要吊销再授予 `revoke`。
仅有 `approve` 不表示可读详情。授权目标须为活跃运维账户和中间 CA。
`issue` 是现有枚举，但没有绕过审批直接签发接口；审批后由任务签发。
所有角色包括超级管理员都不能自审批。账户禁用、密码重置会撤销会话。

## 签发模板

叶申请使用活跃中间 CA 的启用模板。默认叶模板为 90 天、最大 397 天，含
`signing`（digitalSignature）、`key encipherment`、`server auth`、`client auth` 用途。
用途字符串采用 CFSSL 名称。根 CA 默认模板另记录 3 年的 CA 用途元数据，
不属于下面的叶模板限制，也不能用于通过申请接口签发叶证书。

| 字段 | 行为 |
| --- | --- |
| `default_validity_seconds` | 未指定申请有效期时采用，正整数秒 |
| `max_validity_seconds` | 不小于默认值且不超过 397 天，最终受上级链限制 |
| `allowed_dns_patterns` | Go glob；空数组不限制 DNS 范围 |
| `allowed_ip_ranges` | IPv4/IPv6 CIDR；空数组不限制 IP 范围 |
| `allow_email_sans` / `allow_uri_sans` | 默认 false |
| `key_usages` | 至少一项，叶模板禁止 CA 和 CRL 签名用途 |
| `extended_key_usages` | 叶模板禁止 OCSP 签名用途 |
| `enabled` | 仅启用模板可申请；API 省略为 false |

初始模板不会自动形成企业 DNS/IP 白名单，使用前设置实际范围并验证边界。
`policy` 是保存的 JSON 元数据，不能把自定义字段当作已实现的额外校验。
更新采用完整字段输入，不能删除默认或已被引用的模板。

## 申请、审批与下载

优先由客户端生成私钥和 CSR，仅上传 CSR。当前验证 CSR 签名、模板约束，接受
RSA 2048–8192 位或 ECDSA P-256/P-384。通用 CSR 工具可生成 RSA-3072/4096 或
ECDSA P-256/P-384，在当次响应返回私钥，不保存为待领取材料。

服务器生成密钥时提供主题和 SAN。申请从 `pending` 经 `approved`/`issuing` 到
`issued` 或 `failed`；拒绝为 `rejected`。202 不代表签发完成，错误见申请和日志。

签发后可下载 PEM 链。服务器生成的叶私钥仅申请者可领取，保存 24 小时，一次性领取
会在发送响应前擦除服务器材料。直接保存至安全位置；网络或保存失败不能保证重新下载。
使用客户端 CSR 时私钥由客户端保管。

吊销原因码 0–10、排除 7，保存吊销后更新 CRL。核对 CRL/OCSP 实际状态后结束处置；
目前没有取消吊销接口。

## 公开查询和时间戳

公开域名列出活跃 CA，提供签发者证书、CRL、OCSP/TSA，以及按 SHA-256 指纹或
“签发者 slug + 十进制序列号”精确查询叶证书，不提供叶证书全量列表。
精确查询包括 PEM、链、主题、SAN、有效期、状态，也包含 `owner_user_id`、`request_id`
业务 UUID。它们没有匿名化；如业务禁止公开这些元数据，需要另行修改接口和实现。

超级管理员可在活跃中间 CA 下建立 TSU，设置组织控制的策略 OID，见 [TSA](tsa.md)。
验收分别使用三个角色覆盖越权、自审批、模板限制、签发、私钥领取、吊销和公开查询。
测试命令和隔离数据库要求见 [文档入口](README.md)。

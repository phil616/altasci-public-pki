# 独立签发实现与验证记录（2026-11-15）

> 历史检查快照：账户认证已于 2026-11-16 统一为用户名/邮箱和密码；当前操作以 [密码认证](password-authentication.md) 为准。

状态：本次实现的检查快照，不代表线上状态或未来版本持续无漏洞。
范围为独立签发服务、管理与公开 HTTP 接口、前端、迁移、客户端及共享审计事务适配。
所有数据库操作在新建的隔离 PostgreSQL 18.6 容器执行，没有连接生产数据库或部署线上服务。

## 实现与安全边界

- [完整策略与接入](independent-signing.md) 是当前行为依据。采用凭据授权 CSR API，
  不声称 ACME 兼容，也不通过域名挑战判断控制权；名称权限由 CA 所有者明确授予。
- 独立三表只引用用户，不引用系统 CA/证书/模板。重复导入相同 CA 使用不同实例 ID、
  加密 nonce 与 AAD；没有全局 CA 去重。整套签发、吊销和 CRL 测试前后系统 PKI 表数量
  与原 CA 证书保持不变。
- 凭据 256 位随机秘密仅展示一次，数据库存摘要。跨所有者、实例、凭据的读取和撤销均拒绝；
  实例所有者可处理自己的全部记录，超级管理员没有隐式查看其它所有者实例的接口权限。
- 检查 CSR 签名和密钥强度、全部 SAN、CN、Subject、祖先路径深度、完整配置链及每个 EKU。
  不接受 CA/KU/EKU 等 CSR 请求扩展，不联网下载链。路径必须包含配置的所有 CA，避免同名
  同密钥祖先使验证器走捷径跳过约束。请求强度校验在高成本签名验证前执行。
- 签发、额度和审计同事务提交。单次额度的 8 个并发申请仅成功 1 个；审计插入失败时
  证书、额度与幂等状态均回滚。原请求在额度用尽后仍能幂等获取原证书，撤销/过期凭据不能重放。
- CRL 有 critical Issuing Distribution Point，绑定规范实例 URI 与叶证书作用域；
  非规范 UUID 请求不改变缓存作用域。同一 CA 不同实例的 CRL 不能互相替代。
- 单体仍使用外部 Nginx/PostgreSQL；没有新增运行时服务或 Cloudflare 依赖。客户端 Python
  只在调用方需要，服务端不需要 Python。新增直接引用的 IDNA 库原已在 vendor 中，版本未变。

## 验证结果

- Go 应用测试与 PostgreSQL 真实集成测试通过；应用包执行 race 检查通过。
  最后补充配置链约束后，重新执行独立签发与 HTTP 包的数据库 race 测试及所有 Console 包的 vet。
- OpenSSL 解析作用域 CRL 并验证吊销结果；其它实例的 CRL 无法让该证书通过检查。
- 随附 Python 客户端通过真实 HTTPS 发送 CSR、验证 TLS、持久化重试；HTTP 重定向不会
  将凭据送到目标，捕获服务收到 0 次请求。客户端状态/文件写入的 3 项单元测试通过。
- 前端 ESLint、TypeScript、9 项 Vitest、生产构建通过。Playwright 桌面和移动合计
  24 项通过，其中新增流程验证普通用户导入、单次凭据创建、一次展示、刷新后不再展示，
  并检查凭据未进入 localStorage/sessionStorage。浏览器测试的 API 是模拟，数据库行为另行实测。
- 构建单体二进制后实际启动，验证显式迁移、健康检查、两端内嵌资源、本地密码/TOTP 登录、
  CA 导入、凭据、CSR 签发、额度用尽后的幂等重试、OpenSSL 验证、吊销与 CRL，全部通过。
- 文档检查覆盖 65 条显式路由、34 组 JSON 字段映射、12 个配置变量及当前本地链接；
  OpenAPI 3.1 校验和差异格式检查通过。

## 安全工具及人工复核

`govulncheck` v1.9.0 对 `./cmd/pki-console` 报告未发现已知可达漏洞，npm audit 报告 0 个漏洞。
初次使用机器默认旧扫描器遇到 Go 1.27 解析错误，没有将失败计为通过；换用兼容扫描器后重新检查。
这些结果仅限当次数据库、平台和依赖配置，不是无漏洞保证。

使用 gosec v2.30.0 检查 signing/httpapi/store。新增代码的三处诊断经过人工复核后，
使用精确规则的源代码注释说明：SQL 投影列名误报为硬编码凭据，以及两处按正确
`application/pkix-*` 媒体类型和全局 `nosniff` 输出的 DER 被误报为 HTML XSS。
未对整个包禁用规则。其余 6 项为此前报告中的动态生产 Cookie Secure 标志及带指定
非 HTML 媒体类型的 OCSP/TSA/PEM 输出诊断，相关行为没有改动，见
[2026-11-14 安全报告](security-review-2026-11-14.md)。

保留的实际限制包括：共享同一 CA 私钥的信任风险、跨独立副本不能绝对证明序列号不碰撞、
无 OCSP、作用域 CRL 需要客户端正确支持、备份恢复的数据缺口，以及凭据持有者身份无法
细分到共享凭据的具体人员。策略中已说明这些限制。

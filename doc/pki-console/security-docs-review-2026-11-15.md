## 确认问题与处理

严重程度为工程判断，不是正式 CVSS 评分。没有将协议硬化直接认定为已证实的越权漏洞。

| 编号 | 程度与触发条件 | 修正与验证 |
| --- | --- | --- |
| R01 | 中，可用性：公开签发/吊销入口在验证真实凭据之前取得共享运算槽；伪造为合法格式的凭据配合慢请求体可能占用槽位 | 先查询凭据、权限和账户状态，再取得运算槽并读取请求；事务内仍重新授权。测试填满全部槽位，伪造凭据仍立即返回 401，且请求体读取次数为 0 |
| R02 | 低，策略可靠性：部分 URI 路径首次解析成功，序列化时自动转义，后续校验又拒绝百分号；通配符 DNS 长度计算未计入 `*.` | URI 限制为 RFC 3986 不需转义的路径字符，拒绝空片段标记，校验序列化稳定性；DNS 的 253 字节总长包含通配符。加入边界及模糊测试 |
| R03 | 低，输入歧义：标准 Go JSON 解码允许重复字段、大小写别名，顶层 null 可被解释为默认吊销原因；不符合声明的对象契约 | 独立签发输入增加字段名精确匹配、去重、对象/数组类型及非空约束。可选凭据 policy 允许 null，可选身份白名单 null 仍按空名单拒绝处理，保持 Go 客户端兼容性。没有确认可借此绕过已有签发授权 |
| R04 | 低，客户端可靠性：输出路径与凭据/CSR/state/TLS CA 重合时，可能覆盖输入或丢失重试状态 | HTTP 请求之前拒绝相同路径、规范化路径和硬链接别名；增加文件保护测试。异常成功响应不是 JSON 对象时安全退出 |

R01 的预检查只是资源保护：若凭据在请求上传期间被撤销，事务内复核仍返回 401，不能
重放已签发记录或产生新证书。有效凭据的慢请求仍受现有请求超时和并发上限约束；本轮
没有声称消除所有拒绝服务风险。

## 文档与契约规范

- 区分独立签发的必填幂等头与管理 API 的可选幂等头，补齐 413 响应。
- 对齐凭据参数 0 值采用默认值，以及有效期 0 或至少 60 秒的边界。
- 分开可接受 null 白名单的输入策略与规范化为数组的响应策略；标明严格 JSON 规则。
- Bearer 操作增加 `x-signing-scope`，自动核对路由所需 issue/read/revoke 权限。
- 文档检查器核对幂等头必填标志、行内本地链接及 ATX/显式 HTML 锚点，包含 Unicode
  标题和重名标题。故意篡改权限、必填标志和章节引用均被拒绝。
- 明确 HTTPS 在外部 Nginx 终止，后端监听回环；明确客户端输入、状态、输出路径分别指定。
- 历史检查记录保留原日期和结果，当前行为统一由 [独立签发指南](independent-signing.md)
  和 [OpenAPI](openapi.yaml) 说明；检查器限制见 [维护规范](documentation-maintenance.md)。

## 保留边界

本工具不验证域名实际控制权，授权来自凭据及 CA 所有者策略；同一私钥跨实例的信任
风险、作用域 CRL 的客户端兼容性、账户锁定/禁用对凭据的影响、备份恢复缺口、共享凭据
无法定位具体使用者等边界仍存在。密码重置和浏览器退出不会自动撤销独立凭据。
发生凭据或账户泄露时需要单独撤销相关凭据，并按影响吊销证书。

未进行生产环境渗透或长期压力测试，也没有重跑历史 CFSSL 全仓库测试。扫描无发现
不代表不存在未知漏洞。URI 和 JSON 行为参考
[Go URL](https://pkg.go.dev/net/url#URL.EscapedPath)、
[Go JSON](https://pkg.go.dev/encoding/json#Unmarshal) 和
[RFC 3986](https://www.rfc-editor.org/rfc/rfc3986.html#section-3.3)。

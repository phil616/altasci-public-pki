状态：2026-11-15 的二次源码检查和隔离验证记录；线上 TOTP 失败的唯一根因尚未确认。

## 线上日志能确认的事实

提供的日志先出现 `invalid credentials at totp: invalid or replayed TOTP code`，随后出现
`invalid credentials at account_state`。前者说明该次请求已找到 root 且密码校验通过，
后者说明后续请求在禁用/锁定检查就被拒绝，尚未验证 TOTP。按照尝试顺序，连续失败触发
锁定是合理推断，但仍需读取状态确认；`GET /auth/session` 的 401 本身不是密码错误证据。

旧错误将密钥/算法不匹配、过期、重放、旧计数超前合并，无法仅凭该日志判定哪一项成立。
本地运行环境没有该线上服务，未读取其真实配置、密码或密钥，也未更改生产数据库。

## 从配置到验证的复核

| 环节 | 核对结果及处理 |
| --- | --- |
| 环境加载 | 程序只读进程环境，不自动读取 .env；新增捕获环境入口，与启动共用同一解析器，避免诊断采用另一套规则 |
| TOTP 密钥 | Base32 解码后作为 HMAC 的原始字节，不把 Base32 文本或指纹当密钥；验证了小写、分组空格及 20/21/32 字节密钥 |
| root 初始化 | serve 同步环境密码与 TOTP 指纹；原 worker 也执行同步，可能被不同环境的 worker 覆盖，现已移除 worker 的身份写入 |
| 密码 | Argon2id，原始密码字节，恒定时间摘要比较；日志中的 totp 阶段确认该次密码已通过 |
| TOTP 计算 | SHA-256、六位、30 秒、8 字节大端计数、动态截断；RFC 向量通过，HTTP 集成测试改用 OpenSSL 生成提交的代码 |
| 重放 | 时间步已用则拒绝；现在区分已用代码与正确代码被未来计数阻挡，不自动清零或放宽认证 |
| 锁定 | 发现旧计数在锁定到期后不清理，首次失败立即重新锁定；现从 1 开始新窗口，锁定期间不会延长截止时间 |
| 原子校验 | 会话创建仍在行锁事务中复核密码、角色、状态、TOTP 指纹及时间步，拒绝并发过期验证快照 |
| 登录错误 | 已验证密码后可返回 account_locked / totp_replayed；有效代码被未来状态阻挡返回 503 totp_clock_behind，不累计错误凭据 |
| Cookie / CSRF | 登录成功后仍验证 Cookie 会话，写操作仍验证 CSRF；新增错误不会绕过这些检查 |
| 旧 Cloudflare 链路 | 当前登录未调用外部 Access / JWT，历史审计字段不参与认证；没有发送旧网关头的正向登录已覆盖 |

只读 [auth-check](../../cmd/pki-console/auth_check.go) 可捕获 Linux PID 的原始启动环境，
核对数据库中的密码/指纹是否匹配，报告锁定、当前时间步和已用时间步，并可不消费验证码地检验当前输入。
输出不含密码、TOTP 密钥、其指纹、数据库 URL 或输入代码。`--pid` 为 0、错误参数、非六位输入都被拒绝。
捕获 `/proc` 环境不等于验证 Nginx 路由，诊断二进制版本也不等于被检查服务的版本。

## 回归入口与边界

- [配置测试](../../console/config/config_test.go)：启动解析器与捕获环境一致，不能从诊断进程环境补齐缺失的目标配置。
- [生命周期测试](../../console/auth/login_integration_test.go)：锁定到期后的新窗口、未来重放状态、配置不匹配及诊断不修改账户。
- [CLI 测试](../../cmd/pki-console/auth_check_integration_test.go)：连续只读检查后仍可用同一代码登录，成功登录后检查识别为重放；输出无凭据。
- [HTTP 测试](../../console/httpapi/integration_test.go)：使用真实环境解析、root 初始化和 OpenSSL 生成的代码，核对登录、锁定、重放及未来计数的响应。
- [浏览器测试](../../web/e2e/auth.spec.ts)：桌面和手机分别展示锁定、重放和时钟状态异常，不把它们统称为密码错误。

完整测试必须先完成前端构建，再运行使用嵌入目录的 Go 检查。PostgreSQL 测试只在可清空的
隔离数据库执行；浏览器测试模拟 API，真实服务/进程环境的冒烟检查另行记录。
没有证据表明需要删除 TOTP、接受 SHA-1 或关闭生产 Cookie；这些均没有作为解决方法。

前端 lint、类型检查、12 个单元测试、构建及 40 个桌面/手机浏览器用例通过；
4 个 Python 客户端测试和文档/OpenAPI 检查通过。
另外使用实际编译的生产模式单体程序验证：清空诊断进程配置后仍可从指定服务 PID 读取环境，
连续只读核验的代码随后仍可经 OpenSSL/HTTP 登录，成功后识别重放；带不同 root 配置的额外
worker 不会覆盖管理员，诊断能识别该 worker 配置不匹配；模拟未来计数、有效锁定及过期锁定均得到预期结果。
这些冒烟检查连接隔离测试库，未连接线上 Nginx 或生产数据库。
